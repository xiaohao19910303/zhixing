我最近开发了一款美食 App，发现了启动它的场景了：点餐。

## 如何实现？

很简单，将点餐页的 App Linking 链接生成二维码，再通过 图像 API 将二维码和链接发给 Quote/0 就行了，用户扫码和轻碰都会通过 App Linking 跳转到点餐页，进行点餐。

## 如何使用？

- 获取 API Key 和设备 ID，并将图像 API 添加到设备循环任务中。
- 在App 内 Quote/0 设备管理页面添加设备（API Key 和设备 ID）。
- 选择菜品创建菜单，在菜单设置弹窗点击发送到 Quote/0，发送到指定设备。
- 开始点餐吧。

## 关于点餐

目前点餐功能做得很简单，就选择菜品下单，查看订单，发布餐后动态这几项功能，后面再继续完善吧。

关于点餐码，除了菜单点餐码还有用户点餐码，使用用户点餐码时会去查询这个用户的默认菜单或者可用菜单（当没有设置默认菜单或默认菜单未启用时），这样就不用整很多点餐码了，用户只需要修改默认菜单，就能跳转到不同菜单。

目前 App 已上架鸿蒙应用市场，即便你没有 Quote/0 设备，也能和其他鸿蒙设备碰一碰点餐（这也是我先开发鸿蒙端的原因）。

## 又一个美食App?

顺便聊一下这个叫「打尖儿」的美食 App。去年我开发了叫「沽酒家」的诗词 App，企图实现「诗天下」，结果发现诗在远方，不在脚下，这对于一个不愿意出门的人来说，还是挺有难度的。就在我一筹莫展之时，忽然灵光一闪，「诗天下」不行就「食天下」，是不是只需要一口锅就行？相比于「诗天下」，「食天下」是不是更容易实现些？

于是就有了开发「打尖儿」的念头，它只有一个目标，就是「食天下」。所以这款 App 的设计理念就是：每当你发布一条绑定了菜品的动态时，就会自动解锁相关的食材和菜品。如果解锁的这道菜品是某个城市的尖儿菜（用于解锁这道城市的特色菜），那么就解锁了这个城市。如果你解锁了所有城市，那么你就解锁了「食天下」。

我现在的人生目标就是：在家吃遍天下美食。

## 如何创建菜单？

当你有了已解锁的菜品时，你就可以从已解锁的菜品中创建菜单，而不是直接从菜品库里选，主要有两点考虑：

- 用户解锁了，这说明用户会做这道菜，或者吃过这道菜，或者最起码见过这道菜，这样点餐才有意义。
- 用户发布动态时绑定了菜品和图片，所以在菜单里，菜品就展示它在动态里的图片，就不用再管理和配置菜品图片了，点餐的人也能更直观地了解这道菜真实的模样（做这道菜的真实水平）。我个人还是挺喜欢这个设计的，这也是决定我开发这款 App 的关键点。
